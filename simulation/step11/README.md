# Step 11 · simulated browser-to-lab fixture

Run the branch workflow in GitHub Actions. Smoke and the inherited regression jobs are prerequisites. The Step 11 job creates a private network and mount namespace, enables only loopback, installs an ephemeral fixture CA into the browser's NSS trust store, and resolves lab.example through its DNS listener. The browser types the URL into a fixture address form using Chrome DevTools input events and clicks Go, then clicks the experiment button for each trial. The isolated HTTPS gateway accepts the lab.example host on TCP 443 and forwards over a separately authenticated TLS connection to a distinct origin listener.

The Quantum simulation uses a three-qubit complex state vector, an ideal Bell pair, seed 110427 and fixed deterministic trial ordering. A sender process applies CNOT and Hadamard and samples a joint Bell measurement. The conditional recipient slot stays in the simulation backend. The recipient process receives only the two classical bits and proposes X/Z corrections. The backend applies them and measures X/Y/Z probabilities and 64 seeded shots per basis. Ideal preparations are 0, 1, +, −, +i, and −i. The dephasing control averages the equal-weight positive and negative Bell phases. Missing bits expire the lease without invoking the recipient. Link unavailability leaves the page and asset path usable.

The browser receipt records authenticated TLS, HTTP observations and the experiment results. The trace joins DNS and TLS ingress by run and joins page, authorization and simulation by run and trial. DNS may be cached for later trials inside the same browser. Replay reconstructs each simulation from the declared configuration and seed. All quantum results are simulation. The gate provides no physical quantum, public field, or production claims.
